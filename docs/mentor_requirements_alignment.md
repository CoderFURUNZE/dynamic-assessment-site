# 导师要求整理与系统预计处理方式说明

## 1. 文档目的
本文档用于单独整理导师对本课题提出的核心要求，并明确系统中的预计处理方式，便于与导师确认系统建设方向、功能边界和实现口径。

---

## 1.1 预计处理方式摘要
针对导师给出的“融合多元智能理论的学习者画像”结构图，系统中不再把“学习投入/学习成效/学习习惯/学习特征”直接作为一级画像维度，而是改为：

**严格沿用导师图中的 5 个一级维度作为画像主框架**，系统再在每个一级维度下建立 3~4 个二级指标，并在二级指标下挂接可计算的数据项、教师补充评价项和问卷标签项。

也就是说，系统中的画像结构预计采用：

`5个一级维度 -> 若干二级指标 -> 具体数据项/评价项 -> 阶段更新结果`

### 一级维度 1：潜能与特质倾向
对应导师图中的：
- 创造性思维倾向
- 跨情境迁移能力
- 存在思考与价值判断

系统中的预计处理方式：
- 创造性思维倾向：通过开放性任务表现、项目设计表现、教师评价补充形成
- 跨情境迁移能力：通过不同知识点、不同任务情境下的迁移表现进行半自动判断
- 存在思考与价值判断：通过问卷、自评标签、教师观察评价形成

### 一级维度 2：情感与社会性发展
对应导师图中的：
- 协作能力与社交网络
- 学习动机与态度
- 自我调节与元认知

系统中的预计处理方式：
- 协作能力与社交网络：通过小组任务记录、课堂参与情况、教师补充评价形成
- 学习动机与态度：通过资源访问频次、任务完成连续性、阶段参与度等数据推断
- 自我调节与元认知：通过错题回看、补救学习、学习路径调整、教师观察评价进行半自动判断

### 一级维度 3：知识与认知状态
对应导师图中的：
- 跨学科知识关联能力
- 学科能力层级与认知路径
- 语言类知识掌握度
- 逻辑类知识掌握度

系统中的预计处理方式：
- 跨学科知识关联能力：通过知识图谱中的关联节点掌握情况和跨章节迁移表现分析
- 学科能力层级与认知路径：通过知识点掌握顺序、前置知识掌握、阶段变化轨迹分析
- 语言类知识掌握度：若课程存在表达、描述、文本类任务，可单独统计
- 逻辑类知识掌握度：通过练习、小测、知识图谱推理链和逻辑类任务表现分析

### 一级维度 4：学习行为与过程
对应导师图中的：
- 资源偏好：图像/空间型
- 辅助学习策略
- 交互偏好：文本/讨论型
- 交互偏好：实践/体验型

系统中的预计处理方式：
- 资源偏好：通过视频、文档、图像、实验类资源的访问偏好自动统计
- 辅助学习策略：通过复习、回看、错题本、补前置知识点等行为识别
- 文本/讨论型交互偏好：通过讨论、文本学习、资料阅读行为分析
- 实践/体验型交互偏好：通过实验、操作、练习、项目任务参与情况分析

### 一级维度 5：个体基础特征
对应导师图中的：
- 人口学背景与学业经历
- 探究兴趣类型
- 智能优势倾向标签

系统中的预计处理方式：
- 人口学背景与学业经历：作为基础档案信息，不直接参与动态评分，但参与画像展示
- 探究兴趣类型：通过问卷、自评和资源偏好行为共同形成
- 智能优势倾向标签：综合五大一级维度的结果形成标签化输出

### 系统内的实际实现方式
为了让这套结构能落地，系统预计采用“一级维度不变，二级指标分层处理”的方式：

1. 一级维度  
完全采用导师图中的 5 大块，作为系统中学习者画像的主框架。

2. 二级指标  
完全采用导师图中的子节点作为二级指标来源，并允许后续由教师微调。

3. 三级数据来源  
系统把每个二级指标再映射到三类具体来源：
- 系统自动计算项
- 教师补充评价项
- 问卷/标签采集项

### 动态评价如何接入这套结构
动态评价不是绕开这 5 个一级维度，而是按阶段更新这些维度下的二级指标结果。

也就是说：
- 教师每次上传阶段数据
- 系统更新五大一级维度下相关二级指标
- 系统再汇总出当前阶段的主画像结果、扩展画像标签和阶段变化趋势

### 一句话概括
本系统预计采用“**导师图中的 5 大一级维度作为主框架，二级指标作为画像子项，阶段数据/教师评价/问卷标签作为具体来源**”的方式，完成学习者画像与动态评价的系统落地。

## 2. 导师要求的核心理解

根据当前沟通内容，导师对本项目的要求可以概括为以下几点：

### 2.1 动态评价不能只看一次考试结果
导师强调，系统中的动态评价不应停留在单次测验或单次成绩上，而应体现学生在一个学期或多个阶段中的学习变化。

系统应支持：
- 教师按学期或按阶段上传学习数据
- 系统基于新数据持续更新学生画像与评价结果
- 系统能够体现学生的成长变化，而不是“一考定结果”

### 2.2 学习者画像不能只看成绩
导师希望系统中的学习者画像不仅仅反映学生成绩高低，还应从学习行为、学习特征、学习偏好、知识掌握状态等多个维度综合描述学生。

也就是说，系统中的画像应能够回答以下问题：
- 学生当前属于什么类型
- 学生学习是否稳定
- 学生对哪些知识点掌握较弱
- 学生偏向哪种学习方式
- 学生是否存在拖延、波动或知识迁移困难

### 2.3 知识图谱要真正服务教学
导师要求知识图谱不能只是展示课程结构的静态图，而要与教学资源和学习活动真正关联起来。

知识图谱节点应支持挂载：
- 学习资源
- 教学任务
- 练习题
- 小测/试卷

学生点击知识点节点后，应能够直接查看对应内容。

### 2.4 多元智能画像需要纳入系统考虑
导师新增提出，希望学习者画像能够结合“多元智能理论”的思路，不只是做学习成绩和学习行为画像。

这意味着系统中的画像除了主画像外，还应补充体现：
- 学习偏好
- 智能优势倾向
- 协作与社会性表现
- 创造性与迁移性倾向
- 自我调节与元认知特征

但从当前项目落地角度看，这部分更适合做成扩展画像层，而不是直接作为当前主评价分数的核心。

---

## 3. 导师要求在系统中的预计处理方式

为兼顾导师要求与项目可落地性，系统中预计采用“**5个一级维度 + 二级指标映射 + 分层数据来源 + 阶段动态更新**”的处理方式。

### 3.1 一级维度直接沿用导师图
系统中的学习者画像一级结构，不再另起一套，而是直接采用导师图中的五大板块：

1. 潜能与特质倾向
2. 情感与社会性发展
3. 知识与认知状态
4. 学习行为与过程
5. 个体基础特征

### 3.2 二级指标直接来源于导师图中的子节点
每个一级维度下，再采用导师图中已有的 3~4 个子节点作为二级指标。

例如：
- 潜能与特质倾向 -> 创造性思维倾向 / 跨情境迁移能力 / 存在思考与价值判断
- 情感与社会性发展 -> 协作能力与社交网络 / 学习动机与态度 / 自我调节与元认知
- 知识与认知状态 -> 跨学科知识关联能力 / 学科能力层级与认知路径 / 语言类知识掌握度 / 逻辑类知识掌握度
- 学习行为与过程 -> 资源偏好 / 辅助学习策略 / 文本讨论型交互偏好 / 实践体验型交互偏好
- 个体基础特征 -> 人口学背景与学业经历 / 探究兴趣类型 / 智能优势倾向标签

### 3.3 每个二级指标再映射到具体系统来源
为了让这套结构可落地，系统中预计把每个二级指标映射到三类具体来源：

1. 系统自动计算项  
适合通过阶段学习数据、学习行为记录、知识图谱关系自动分析的内容

2. 教师补充评价项  
适合由系统提供证据、教师补充判断的内容

3. 问卷/标签采集项  
适合通过学生自评、问卷、互评或标签选择形成的内容

### 3.4 系统中的画像输出方式
系统最终不只输出一个“总标签”，而是分层展示：
- 一级维度结果
- 二级指标标签或分项结果
- 当前阶段变化说明
- 教师补充评价

### 3.5 系统中的应用方式
这套结构在系统中主要服务于：
- 学生画像展示
- 阶段动态评价
- 教师分析
- 个性化推荐

其中需要明确：
- 阶段动态评价主要由可计算指标驱动
- 多元智能相关维度通过系统自动分析、教师评价和问卷结果共同补足
- 系统不会把所有二级指标都强行量化成一个总分，而是更强调结构化画像和阶段变化

---

## 4. 动态评价在系统中的预计实现方式

导师要求中的动态评价，系统中预计按以下方式实现：

### 4.1 数据更新方式
- 教师在每个学期内按阶段上传一批学习数据
- 系统读取该阶段数据并提取画像特征
- 系统更新该学生在该阶段的学习画像和评价结果

### 4.2 评价输出方式
系统每个阶段输出：
- 阶段画像结果
- 阶段评价得分
- 阶段变化趋势
  - 进步
  - 持平
  - 退步
- 风险提示
- 教师补充评价

### 4.3 知识图谱在动态评价中的作用
知识图谱参与动态评价的方式包括：
- 判断当前知识点是否存在前置知识未掌握
- 判断学生薄弱点是否集中在某类知识结构上
- 支撑推荐路径和补救路径生成
- 支撑节点级掌握度分析

也就是说，系统中的动态评价不只是行为统计，还会结合知识图谱结构判断学生的问题出在哪里。

---

## 5. 知识图谱模块的预计处理方式

导师要求知识图谱服务教学，因此系统中预计按以下方式实现：

### 5.1 教师端
教师负责：
- 创建课程知识点
- 维护前置关系和关联关系
- 绑定资源、任务、练习和小测/试卷
- 在图谱工作区直接编辑知识图谱

### 5.2 学生端
学生可以：
- 进入知识图谱学习地图
- 点击节点查看知识点详情
- 查看节点对应的资源、任务、练习和小测
- 查看节点掌握状态和推荐信息

### 5.3 节点详情内容
知识图谱节点点击后，系统预计展示：
- 知识点标题与简介
- 当前掌握度
- 前置知识点
- 后续知识点
- 学习资源
- 教学任务
- 练习题
- 小测/试卷

---

## 6. 当前建议的系统处理原则

为保证系统既符合导师要求又能顺利落地，预计采用以下原则：

### 6.1 主评价模型保持稳定
当前主评价仍以：
- 学习行为数据
- 阶段导入数据
- 知识点掌握情况
- 知识图谱结构

为主要依据。

### 6.2 多元智能画像作为扩展画像层
多元智能相关内容进入系统，但不直接替代当前主评价逻辑。

这样做的原因是：
- 当前项目数据更适合支撑学习状态画像
- 多元智能部分如果全部做成自动评分，容易缺乏可靠依据
- 采用“扩展标签层”更符合当前系统落地条件

### 6.3 教师补充评价作为关键桥梁
对于无法完全自动计算的维度，系统应允许教师基于观察和教学经验补充评价，从而提升画像的完整性和可信度。

## 8. 当前建议发给导师确认的表述

建议发给导师的说明如下：

> 老师，我根据您提出的“融合多元智能理论的学习者画像”方向，对系统中的画像设计做了进一步梳理。  
> 目前系统预计采用“两层画像”方式：  
> 第一层是动态学习画像，主要根据教师按阶段导入的学习行为数据自动生成，重点反映学习投入、学习成效、学习习惯和学习特征，这一层直接参与当前的动态评价；  
> 第二层是多元智能扩展画像，主要体现学习偏好、智能优势、协作倾向、创造性和迁移倾向等特征，这一层准备通过系统自动推断、教师补充评价以及问卷/标签采集三种方式形成，作为学习者综合画像和个性化推荐的补充依据。  
> 同时，知识图谱在系统中不仅用于展示课程结构，还会与资源、任务、练习和小测进行绑定，并参与知识掌握分析和推荐路径生成。  
> 这样处理后，系统既能保持当前主线可落地，也能与多元智能学习者画像的研究方向保持一致。  
> 请老师看看这种处理方式是否符合预期。

---

## 9. 结论
当前系统预计采用：

`主画像 + 多元智能扩展画像 + 知识图谱 + 阶段动态评价`

的整体处理方式。

其中：
- 主画像负责当前动态评价主链
- 多元智能扩展画像负责补充学生综合特征
- 知识图谱负责结构化分析知识掌握与推荐路径

这种处理方式能够兼顾导师要求、系统落地性和后续论文表达的一致性。
